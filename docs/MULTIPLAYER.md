## Команда (разобрано 2026-11-27)

Все действия в миссии (игрок, ИИ, Lua, последствия выстрелов, предпросмотр) идут через одну функцию:

```
void ActorSimulator::RequestAction(ActorSimulator *sim, Actor *actor, int actionIndex, const Target *target, bool flag)   // 0x38b9b0
```
- `actor->actions` — вектор `{first,last,end}` по `+0x50`, элементы по `0x38` байт, первым полем `std::string` имя действия;
  `actionIndex` — индекс в нём. Индекс по имени: `0x2bcdd0(actor, string_view)` (так ИИ ищет `enemy_aim`).
  Определение действия — по имени в карте `0xeb07c0`; `def+0x110` — битовая маска допустимых типов цели.
- `*(int*)*actor` — id актёра (печатается в «Actor {} attempted …»; совпадает ли с Lua-хэндлом — проверит лог).
- Если актёр свободен (`actor+0x1b4 < 0`, `actor+0x1d8 == 0`, `0x2bd160(actor) < 0`) — сразу `0x391e30` (выполнить),
  иначе запрос `{index, Target, flag}` встаёт в очередь актёра (deque `actor+0x1b8`, элемент 0x38).
- `Target` — `std::variant`, 0x20 байт данных + индекс (байт) по `+0x20`; копирование/уничтожение — таблицы
  `0xb98c30`/`0xb98c60`. Типы и конструкторы:

| # | Что | Данные | Конструктор | Кто |
|---|---|---|---|---|
| 0 | без цели | — | `0x43a930` | эвакуация, способности на себя |
| 1 | точка (2 float) | 8 байт | `0x43a9d0` | ИИ (`order+0x158`), конец снаряда (`EndProjectileAction`) |
| 2 | id актёра/сущности | int | `0x388900` | ИИ (`order+0x178`), действие с объектом после движения |
| 3 | угол прицела | float | `0x43aa70` | выстрел игрока (`0x4595c0`) |
| 4 | путь движения | vector<16 байт> + 8 байт | `0x3889a0` | движение (`0x38c2c0` строит путь сам) |
| 5 | список | vector<8 байт> | `0x43ab10` | ИИ (`order+0x180`) |

  Все типы — простые данные (указателей на объекты мира нет) → **команду можно передать по сети байтами**.
- `flag` = 1 у вторичных запросов (прицел ИИ `enemy_aim` перед выстрелом, эвакуация, действия снарядов).
- Кто вызывает (по адресу возврата): игрок `0x455eb0…0x45e000` (подтверждение — `0x4592b0` движение/взаимодействие,
  `0x4595c0` выстрел с углом, `0x4597c0` цель-актёр/без цели, `0x459a10` точка, `0x45b920`, `0x45bc40` эвакуация),
  ИИ `0x43be40` (приказ: индекс действия `order+0x198`), Lua `MoveActorTo` и др. → `0x38c2c0`, снаряды `0x462e30`,
  предпросмотр `0x4548e0` (на КОПИИ мира — свой `ActorSimulator`).
- Актёры мира: `sim+0x10` = мир; `0x123a00(world+0x1c48, &out)`; список `std::list` в `[out[0]+0xd0]`, актёр встроен
  в узел по `+0x18` (так же ходит `IsActionsOngoing` = `0x38e1e0(sim)`).
- `sim+8` = реестр симуляторов (`S`); объект «конец хода фракции» = `[S + 8 + 8*[0xea9068]]`, функция
  `FactionDone` = `0x484f60(obj)` (её зовут Lua `SetCurrentFactionDone`, конец хода врагов `0x43ac30`, менеджер ходов
  `0x4840a0`, диалог эвакуации `0x45bee0`). Через что идёт кнопка «конец хода» игрока — покажет лог (`end o=…`).
- `ActorSimulator::Update` `0x3896d0(sim, arg)` — каждый кадр мира (и на копиях предпросмотра).

## Автоматический прогон (с 2026-11-27 — основной способ)

Пользователь не нужен: игра сама входит в миссию, играет и закрывается, результат — текстом.
```
swh2 install --only CheatMenu,Coop,MoreSlots,Turbo --set Turbo.playerSpeed=3 --set Turbo.enemySpeed=4   # Coop с netTest
swh2 nettest run 6 --autoplay     # новая запись: команды игрока из текущей записи, остальное — как при обычной записи
swh2 nettest run 6                # повтор против неё + сравнение (DIFF/FIX/расхождения)
```
- Слот 6 = банк `nettest start` (начало миссии west_caribbea_23 с вступительным диалогом). Оригинальная запись
  пользователя — `swh2_net_record_user_run6.log`.
- `NetTest.Run`: кладёт банк в слот, пишет `swh2_net.txt` (`record`/`replay`/`autoplay`) и сценарий автопилота
  `swh2_net_autorun.txt`, на время прогона ставит игре оконный режим (`settings.xml` `Screen.Fullscreen`, потом
  возвращает), запускает exe, ждёт `# replay finished` / `# mission over` / тишину в логе, убивает игру, сравнивает.
- Автопилот (`swh2coop.c`, только при netTest): вставляет нажатия клавиш в поток SDL-событий игры (окно может быть
  в фоне, другие программы не трогаются; игре шлётся «фокус получен», «фокус потерян» отбрасывается). Команды:
  `enter <ms>` (Return, пока не пойдёт мир миссии: интро, титул, слот — курсор уже на самом свежем сейве),
  `cutscenes on` (Return раз в секунду, пока Lua говорит, что идёт диалог/камера: `swh2_net_cutscene.txt`),
  `popups on`, `key`, `pad`, `wait`. Слепо жать Return нельзя: в тактике Return = «выполнить действие».
- Повтор не шлёт команды, пока идёт диалог/камера и 90 кадров после (иначе игра зависает на пустом диалоге).
- Lua пишет `# mission over: victory|crew lost` (своего колбэка поражения у игры нет — «экипаж был и кончился»).

Что сделано для совпадения (прогоны 7–9):
- **Коррекция состояния** (гость = повтор): перед каждой командой игрока dll просит Lua (`swh2_net_sync.txt` →
  `coop.lua C.netFix`) поставить состояние из записи (`state`-строка перед этой командой): позиции
  (`SetEntityPosition(a, Vector(x, y), false)`), здоровье, лишних — `KillObject`. В логе `# FIX`/`fix N …`.
- **Фиксированный шаг мира**: `0x480a10(world, game, float *dt)` получает шаги по 1/60 с (накопитель, ≤4 за кадр).
  До этого один и тот же выстрел врага при одинаковом ГСЧ в записи промахнулся, в повторе попал.
- **ГСЧ спавнов**: `SpawnReinforcements` `0x4099f0` и спавн у входа `0x40aae0` пишут `spawn r=`, повтор ставит ГСЧ
  (подкрепления появлялись другими типами — косметика тратит ГСЧ между концом хода и спавном).
- Вызовы с `outcomesimulator.cpp` в стеке, но на ГЛАВНОМ мире (`sim == mainSim`) больше не считаются предпросмотром.
- Хвост узлов пути (4 байта мусора — остаток указателя) обнуляется в логе и при сравнении.
- Блокировка ввода при netTest выключена (тест одиночный; в уровне 2 у каждого своя игра).
- **ИИ гостя выключен** (см. ниже).

Результаты до выключения ИИ: 73/73 дважды, потом 49/71: враг у гостя «передумывал», его ИИ сам выбирал, кто ходит.

### ИИ гостя выключен (2026-11-27)
- Повтор (`replay`, не `autoplay`) = гость: симулятор хода врагов `0x43ac30` не вызывается вообще (он запускает
  расчёт ИИ, выполняет приказы через `0x43be40` и сам может звать `FactionDone`), шаги ИИ `0x4487b0` тоже. В логе
  повтора нет ни одной строки `ai`.
- В сценарий повтора идут команды ИИ верхнего уровня и **все** концы ходов, в порядке записи. Команды ИИ насос выдаёт
  через 45 кадров простоя (`fl=1` ИИ, т. е. `enemy_aim`, тоже, в отличие от автодействий игрока). Конец хода, который
  игра даёт сама (игрок после последнего AP, Lua, менеджер ходов = `o=other`), засчитывается за запись. Через 150 кадров
  он выдаётся принудительно. В логе повтора у команд ИИ стоит `o=ai`, а не `o=replay`.
- Ход врагов закрывает **менеджер ходов** (`0x483b40`/`0x484c60` → `0x4840a0` → `FactionDone`, отсюда `end o=other`),
  когда ничего не идёт, список «кому ещё ходить» (`[turn+0x18]+0x48`, `vector<int>`) пуст и ни у кого нет годных AP
  (`actor+0x90`). Исполнитель приказов ИИ сам пишет `[actor+0x90] = 0` после приказа, в обход `RequestAction`, поэтому
  у гостя враг, который только сходил, оставался с AP, и ход не кончался. Принудительный `FactionDone` давал второй,
  вложенный конец хода (менеджер в том же кадре), и тот съедал следующий записанный (конец хода игрока). Поэтому при
  записанном `end o=other` гость вызывает «конец хода актёра» `0x390e20` для всех актёров фракции и очищает список
  (`FinishFaction`, в логе `# turn end N: the host's AI was done, turn of K actors ended`). Дальше игра закрывает ход
  сама, одним вызовом, как у хоста.
- Прямой вызов `0x390e20` из ИИ (`0x43cf9c`) пишется как команда `i=-1 n=@done`, и гость выполняет её так же. В
  проверенных прогонах её не было.
- Результаты (`tools/nettest_cycle.sh`): повтор против старой записи — 71/71; свежие запись + повтор три раза подряд —
  52/52, 56/56, 45/45; ещё одна запись, где раньше падало, — 53/53. Везде 0 `DIFF`, коррекции ничего не меняли.

## Сеть, шаг 1: хост → гость по TCP, гость смотрит (2026-11-27)

- **Протокол = лог.** Хост — записывающая игра, гость — повторяющая. `native/nettcp.c`: у хоста поток слушает порт
  и отдаёт подключившемуся гостю свой лог (`swh2_net_record.log`) с первого байта, дальше — каждую законченную строку
  (опрос файла раз в 15 мс). У гостя поток подключается (повторяя попытки), обнуляет свой `swh2_net_replay.log` и
  дописывает в него принятое. Потоки трогают только файлы и сокеты, игру — нет.
- Повтор гостя читает файл **по мере роста** (`ReadMore`, раз в 4 кадра): законченные строки, остаток — в следующий
  раз. Перед созданием сцены миссии и перед спавном гость **ждёт** нужную строку хоста (до 180 / 20 с, игра на это
  время стоит). Конец хода, который игра гостя дала раньше, чем пришла строка хоста, засчитывается, когда она придёт.
  Lua-коррекция (`coop.lua C.netFix`) перечитывает запись, если нужного `state` в ней ещё нет. «`# replay finished`»
  живой гость не пишет.
- `swh2_net.txt`: `<режим> [host [адрес:]порт | connect адрес:порт]`. `record host 27015` — слушать на всех адресах
  (Windows один раз спросит про брандмауэр); `host 127.0.0.1:27015` — только этот ПК; `replay connect 1.2.3.4:27015`.
- **Тест на одном ПК**: `swh2 nettest net 6 [--guest DIR] [--port N]` (`NetTest.RunNet`) — Steam-копия = хост
  (экземпляр 1, автопилот по текущей записи, `autoplay host 127.0.0.1:27015`), через 8 с GOG-копия = гость
  (экземпляр 2, `instance2\`, `replay connect`). Гостю — тот же стартовый сейв в его слот (`<data>\Save000` — сейвы GOG
  лежат там, у Steam — `<data>\<аккаунт>\Save000`; старый файл слота — `.nettest-kept`). Конец — «mission over» у гостя
  или тишина в его логе; сравнение: запись хоста против `instance2\swh2_net_replayed.log`. Обе копии должны быть
  установлены с Coop → Netplay test. GOG грузит сейвы Steam-копии (проверено).
- Автопилот при тестовом прогоне не пропускает в игру настоящие события мыши: наведение указателя на окно ставило курсор
  титульного меню на Options, и Return автопилота открывал настройки (прогон висел). Позицию указателя игра берёт
  только из событий (`SDL_GetMouseState` — лишь кнопки, `0x7f5362`).
- Прогоны без вмешательства: 52/52, 52/52, 51/51; ещё один 9/9 (хост играл по обрезанной записи). Везде у гостя 0 `DIFF`.
  Прерванный прогон оставляет обрезанную запись: следующий автопилот хоста будет коротким.
- Результат первого прогона: **52/52 контрольных точки**, у гостя 0 `DIFF`, коррекции ничего не меняли. Хост в тесте
  играет автопилотом по старой записи: когда её команды игрока кончаются, хост стоит — прогон кончается по тишине.

**Следующие шаги** (решено с пользователем 2026-11-27):
1. **Команды гостя**: гость управляет своими персонажами, его команды уходят хосту, хост выполняет их и пишет в свой
   лог (дальше — как сейчас). Обратный канал в том же TCP-соединении.
2. **Распределение персонажей** (формат пока — 2 игрока, хост + 1 гость): по очереди — 1-й персонаж хосту, 2-й гостю,
   3-й хосту… Полное ручное распределение — потом. Чужих персонажей локально выбрать нельзя.
3. **UI**: при запуске миссии — цвет рамки персонажа + подпись, чей он; в миссии — то же (подписи Coop уровня 1 — основа);
   статус сети (хост/гость, подключён ли, чей ход). Для этого разобраться с UI игры.
4. Прогон гостя с другим FPS; потом Steam-транспорт (лобби, приглашение) вместо IP.

## Сеть, шаг 2: команды гостя, делёжка экипажа, HUD (2026-11-27)

- **Обратный канал** — то же TCP-соединение (`nettcp.c`: `NetTcpSend` у гостя, у хоста поток кладёт строки в очередь,
  игра забирает `NetTcpPoll`). Строки гость → хост: `gcmd ao= i= t=<тип>:<hex> to= fl= f=<кадр гостя>` и
  `gend n=<сколько концов хода хоста гость прочёл>`.
- **Гость**: команда игрока (`PlayerTurnSimulator`, `fl=0`) у себя НЕ выполняется — уходит хосту (`# to host:`), пока
  она в пути, следующие (кроме того же кадра: движение + дверь) отбрасываются, через 600 кадров ожидание снимается.
  Свой конец хода (кнопка или автоконец после последнего AP) тоже не выполняется — `gend`; хост кончает ход, только если
  это всё ещё тот ход (`n` = его число концов хода), иначе «устарело». Автодействия (`fl=1`), которых ещё нет в логе
  хоста, гость оставляет хосту. Команда возвращается в логе хоста и повторяется как обычно.
- **Хост** (`HostPump`): когда мир свободен, выполняет команды гостя (`replaying`, в логе `o=player … by=guest`), команды
  одного кадра гостя — подряд. Отказ, если актёр не найден или он хоста.
- **Делёжка** (2 игрока): Lua миссии пишет экипаж в порядке появления (`swh2_net_crew.txt`, id, новые — по id, павшие
  остаются; `coop.lua C.netCrew`), dll: 1-й хосту, 2-й гостю, 3-й хосту… (`# owners: 41=host 42=guest`). Обе игры
  делят один и тот же бой — договариваться не нужно. Не из экипажа (союзники миссии) — ничьи.
- **Чужих выбрать нельзя**: хук «можно ли выбрать» `0x45ac50(pts, id) -> bool` (фракция игрока, AP > 0…; его зовут
  `SelectActor` `0x45a210`, переключение Tab, выбор в начале хода `0x45b690`, портреты `0x5fb…`) отвечает «нет» для
  чужих. Автоконец хода от него не зависит (решает менеджер ходов по AP). Выбранный актёр: `[[pts+0x18]+0x40]`
  (или `[world+0x1ed4]`), выбранное действие `[pts+0x30]`, указатель на актёра `0x459c40(pts)`.
- **HUD**: dll раз в 0,5 с пишет `swh2_net_status.txt` (`host|guest`, состояние связи, у скольких персонажей хоста/гостя
  есть AP); Lua (`C.netStatus`) показывает два счётчика (`counters.xml` `coop_net_*`, только текст, без эффектов):

- **Выстрел гостя кончается иначе — разбор (2026-11-28).**

    (`SetEntityDirection`, `fix … turned=N`), сравнение теста его проверяет. Перед расходящимся выстрелом направления

    (`damagesimulator` → `0x3e89c0`). **Исправлено**: `CosmeticRng` перенаправляет 22 загрузки указателя на ГСЧ в этих
    функциях на свою ячейку рядом с exe (второе состояние ГСЧ), только в сетевой игре. После этого шаги мира тянут
    общий ГСЧ одинаково (крит 27/27), трассы ГСЧ хоста и гостя совпадают. Плюс мировой ГСЧ: на фиксированных шагах
    своё состояние, ставится в точках синхронизации (`RngMark`).
  - Углы прицела бойца (`+0xe0`/`+0xe4`) у бойца гостя перед выстрелом одинаковые (0/0).
  - Тот же выстрел гостя (ГСЧ, угол, позиция, направление, углы прицела совпадают) у гостя снимал 1 HP, у хоста — 0.
    **Причина — позы (разбор 2026-11-28, Coop 2.3.0; в игре не проверено).** Попадание считается по частям тела
    (`bodyparts.xml`: head — криты, shield — 0 урона, ноги — хромота; шляпа слетает), полигоны частей там, где их
    поставила скелетная анимация. Что нашлось в exe:
    - Скелеты двигаются **раз в кадр по времени кадра, вне мира**: метод `0xc3ad0` (vtable `0xb7ea78`, соседний с
      Update `0xc2080` → `0xc26a0` → мир) зовёт `0x37c100(world+0x3f8, dt, x)` и симулятор скелетов
      `0x57c4d0(world+0x388, dt, x)` (`skinnedcharactersimulator.cpp`; dt = кадр × масштаб времени, x = `[кадр+0x50]`).
      Предпросмотр исхода зовёт те же два после каждого своего шага мира (`0x4551e0`/`0x4551f7`, x = 1.0).
      `AnimationSimulator` (`0x564530`, логика переходов) — внутри мира, на шагах.
    - `0x57c4d0` **пропускает персонажей вне камеры** (прямоугольник `world+0x1c34`: x, y, w, h): их поза стоит, пока
      они не попадут в кадр, — у каждого ПК своя камера. Персонаж держит время своего последнего обновления (`+0xd0`),
      общее время симулятора — `+0x250` (double).
    - Новая анимация начинается со **случайной точки цикла**: `0x56529d` (случайное × длина анимации), а новый
      компонент анимации получает случайное зерно (`0x563630`, место `0x563700`). Оба тянули косметический ГСЧ — свой
      на каждом ПК.
    - Мир получает не `float *dt`, а `{ float dt; double time; }` (предпросмотр кладёт время копии `+0x26a8`), мир
      передаёт его своим симуляторам. Хук шага подсовывал голый float — `time` был мусором со стека.
    - И главное: даже на фиксированных шагах между двумя командами у хоста и гостя проходило **разное число шагов**
      (ожидание друг друга, сеть, загрузка) — фаза idle-анимаций и всё на таймерах расходились.

    **Сделано** (`netplay.c`): позы — после каждого фиксированного шага мира (dt × масштаб времени, x — последний из
    кадра), вызовы кадра получают dt 0 (по адресам возврата `0xc3dec`/`0xc3e02`); на время наших вызовов камера —
    «весь мир». Структура dt копируется, `time` = шаги × 1/60. Третье состояние ГСЧ (`animRng`) для `0x56529d` и
    `0x563700`, ставится вместе с мировым (`RngMark`). **Lockstep**: счёт шагов мира от сцены (`worldSteps`), хост
    пишет его в `cmd`/`end` (`w=`) и строками `k <шаги>` каждые 6 шагов; мир гостя держится (обновления с dt 0, как
    пауза) на шаге следующей записи хоста (или последнем известном шаге хоста), `Pump` выдаёт запись ровно на её шаге.
    Отстал > 20 шагов — ×3, > 600 — счёт с шага хоста. Не держится, пока идут действия или диалог/камера, и после
    1200 кадров ожидания; ушёл вперёд — счёт продолжается от следующей записи (`# world steps: … counted from here`).
    Вход с сейва хоста — счёт с первого шага хоста после сейва (фазы бойцов, ещё не ходивших, тогда не совпадают).
    Старые записи без `w=` повторяются как раньше. Остаточный риск: команда хоста могла прийти внутри шага мира, гость
    выдаёт её из `ActorSimulator::Update` — порядок подсистем внутри одного шага может дать сдвиг на шаг.
    Проверить: `swh2 nettest run 6 --autoplay`, затем `swh2 nettest run 6` — выстрелы гостя без `FIX`, в логе повтора
    мало строк `# world steps`.
- **Статус из сетевого сейва в одиночной игре**: такой сейв нёс строки `coop_net_*` («Хост · ждём второго игрока») и в
  одиночной игре — Lua их не трогал. Теперь без сети `C.netClearStatus` снимает их один раз за бой.

## Моды и запуск сетевой игры (2026-11-27)

- **Разделение**: `Mods/Coop` = сетевая игра (NE Co-op (network) 2.0.0), `Mods/RemoteCoop` = прежний режим через Parsec
  (NE Remote Play Coop). Общие части — `Mods/Coop/CoopShared.cs` (`CoopInstall`), Lua `Mods/Coop/Lua`, dll

  (`CoopInstall.CheckAlone`). Настройки игроков/устройств/блокировки ввода — только у RemoteCoop.
- **Coop без галочки**: exe всегда помечен `NET1`, но dll ничего не перехватывает (кроме сердцебиения ввода), пока
  нет `swh2_net.txt` (тесты) или `swh2_net_session.txt` (сетевая игра). Сессию пишет окно загрузчика
  **Network game…** (`NetPlayForm`, `NetSession.Start`) или `swh2 nettest play host [PORT] | play join ADDR[:PORT]
  [--name NICK] [--no-launch] [--data DIR]`: `host [адрес:]порт` / `join адрес:порт` + `name <ник>`. dll читает её один
  раз и переименовывает в `swh2_net_session.used.txt` → следующий запуск игры одиночный. Хост = `record host`, гость =
  `replay connect` (те же пути, что в тестах). Профиль окна (ник, режим, порт, адрес) — `swh2_coop_profile.txt`.
- Тестовые прогоны удаляют `swh2_net.txt` после себя (`NetTest.ClearControlFiles`). Автопилот (`swh2coop.c`) включается
  только при `swh2_net_autorun.txt` (иначе он глушил бы мышь живым игрокам).
- **Ники**: хост пишет в лог `name host <ник>` (гость читает его из потока), гость при каждом подключении шлёт
  `hello <ник>` (`NetTcpSetHello`), хост пишет `name guest <ник>`. Тексты с именами (`CoopMod.NameKeys` = `nameKeys`
  в netplay.c: `coop_owner_1/2`, статус HUD) ставятся с «Host»/«Guest», у каждого есть шаблон `coop_tpl_<ключ>` с `{1}`

  карта `+0x100` (открытая адресация: ёмкость `+0x18`, управляющие байты `+0x20`, записи `+0x28` по 0x40: ключ
  `std::string`, значение `std::string` `+0x20`), поиск `0x166110(map, std::string*) -> индекс`, длинный текст — буфер
  из `operator new` игры `0xa05748`. В тесте: `swh2 nettest net 6 --guest-plays --names Алиса,Bob` (строка
  `name …` в `swh2_net.txt`). Подписи на портретах (`#coop_owner_N` в ui.me) берут текст при создании слота.
- **Портреты**: слот `0x5fa900(slot, int, std::string *persona)`, картинка `0x745de0(image, string_view*)`, дочерний

## Первая игра людьми: ноутбук + ПК (2026-11-28) и что исправлено

Логи гостя пользователь прислал архивом, хоста — `%APPDATA%\…\swh2_net_record.log` (запись той игры; перед
`nettest net` её перезапишет восстановление из `swh2_net_record_user_run6.log`). Найдено и сделано (Coop 2.1.0, **в игре ещё не проверено**):
- **Проверка модов отказывала при одинаковых исходниках**: хеш `swh2coop.dll` разный при сборке разными версиями MSVC.
  Теперь `build.cmd` вшивает id исходников (`srcid.ps1`: SHA-256 исходников с LF; `SWH2COOP_SRC=` в dll, экспорт
  `Swh2CoopSource`), загрузчик сравнивает `dll=src:<id>` (`NetSession.DllId`; старая dll — `file:<хеш>`), `data=` —
  по пакам (`Game.pak:<хеш>,Game2.pak:original`), ошибка пишет, что именно отличается. Профиль окна (ник, режим,
  адрес) сохраняется сразу и при закрытии окна (раньше — только после удачного старта).
- **Зависание №1 — «подождать» у гостя**: кнопка идёт не через `RequestAction`, а `PTS 0x45bb20` → `0x390a90` (одно
  действие) / `0x390930(sim, actor, -1)` → `EndActor`. У гостя боец заканчивал ход только локально, хост ждал его
  вечно. Теперь хук `0x45bb20`: гость шлёт `gcmd … i=-2` (цель = индекс выбранного действия), хост и повтор гостя
  делают то же, что кнопка (`RunWait`), в логе `cmd … i=-2 n=@wait t=2:<индекс>`.
- **Зависание №2 — оба походили, ход не кончился**: автоконец хода делает `PlayerTurnSimulator`, а команды по сети не
  его; если последней была команда гостя и игра гостя тоже не закончила ход — ждали оба. Хост (`TurnWatch`) сам
  заканчивает ход, если экипаж в этом ходу действовал, мир тих 120 кадров и ни у кого из фракции нет AP.
- **Хук загрузки чекпоинта не ставился** (`ERROR: checkpoint hooks not installed` у обоих): в ожидаемых байтах
  `0xc7410` потерян REX-префикс `0x40` у `push rdi`. После загрузки чекпоинта хостом гость «терял» бой.
- **Задержка у гостя** (действие видно через 2–5 с): ожидания файлового повтора (45 кадров простоя, коррекция,
  ещё 45; 150 перед автодействием; 90 после каждой камеры) — для живого гостя 4 / 40 / 20 кадров.
- **Два бойца в одной клетке**: хост помнит узел назначения последнего хода каждого своего бойца (первый узел пути),
  ход гостя в такой узел отклоняется строкой `refused ao=<n> cell` (гость снимает ожидание команды, над бойцом —
  текст `coop_net_refused_cell`). Другие отказы хоста теперь тоже доходят до гостя (раньше гость ждал 600 кадров).

## Тест записи и повтора (шаг 3) — как запустить

DLL мода Coop (`native/netplay.c`) перехватывает `RequestAction`, `FactionDone` и `Update` (инлайн-хуки: 14-байтовый
`jmp`, трамплин со скопированным прологом; пролог сверяется побайтно). Источник вызова — по адресам возврата.
**Всё по шагам делает окно загрузчика** (Coop → кнопка **Netplay test…**) или `swh2 nettest …` (`Mods/Coop/NetTest.cs`):
0. В настройках Coop включить **Developer → Netplay test** (блокировку ввода можно выключить), Apply.
1. Сохраниться посреди миссии (враги живы) → **Store slot as test start** (банк `nettest start`).
2. **Record run**: банк → слот, `swh2_net.txt = record`, запуск игры. В игре: загрузить слот, сыграть пару ходов
   (пусть враги походят), выйти. Лог `swh2_net_record.log`: `cmd` (кто, актёр `a=` и его порядковый номер `ao=`,
   действие, цель байтами, `to=` — номер актёра-цели, флаг, ГСЧ, счётчик), `end`, `turn`, `actor <id> o=<n>`,
   `ai` (шаги расчёта ИИ), `state` (Lua: все актёры `id@x,y#hp` после каждого завершения действий).
3. **Replay run**: запись → `swh2_net_replay.log`, банк → слот, `swh2_net.txt = replay`, запуск. В игре загрузить
   слот и ничего не трогать. Повтор: команды игрока — когда мир свободен 45 кадров и записанное до них уже прошло
   (команды одного кадра записи — сразу подряд); автодействия игры за игрока (`fl=1`, перезарядка после последнего
   выстрела) и конец хода — ждём, что игра сделает их сама, через 150 кадров — принудительно. **ИИ у гостя
   выключен** (с 2026-11-27, раздел «ИИ гостя выключен»): команды врагов и концы ходов идут из записи в её порядке, как
   команды игрока. Перед каждой командой/концом хода ставятся записанные ГСЧ и счётчик id (только вперёд).
   Лог — `swh2_net_replayed.log`.
4. **Compare** — первое расхождение по контрольным точкам (команды верхнего уровня, концы и начала ходов +
   состояние перед ними; актёры — по порядковым номерам), где расходятся ГСЧ/счётчик, и заметки `# DIFF` повтора.
Ограничения: одна миссия за запуск игры (счётчики не сбрасываются).

### Результаты прогонов

**Прогон 1 (2026-11-27, west_caribbea_23, 4 хода, ДО синхронизации счётчика id):**
- (а) id актёров из сейва совпадают (41, 42, 157). **id появившихся по ходу врагов — нет** (209 → 208, 252 → 244,
  299/300 → 295/296): номера выдаёт `0x742db0` = `++[entityManager+0x58]`, `entityManager = world+0x1c48`, и тем же
  счётчиком нумеруются спецэффекты (`SpawnSpecialEffect*`) → косметика сдвигает id. Отсюда главное расхождение:
  удар ближнего боя по цели `209` при повторе ушёл в пустоту, враг `208` выжил и ударил. Исправление: счётчик
  синхронизируется вместе с ГСЧ (поле `e=` в логе). Для сети — то же: хост шлёт счётчик с каждой командой и концом
  хода (запасной вариант — таблица «id хоста → локальный id» по порядку появления актёров).
- (б) **Прямой вызов `RequestAction` работает**: движение, выстрел, дверь, ближний бой, перезарядка, ожидание —
  позиции и здоровье после них совпали с записью до точки; AP тратятся, ход кончается.
- Ход игрока игра заканчивает **сама** после последнего AP (`end o=player` из `PlayerTurnSimulator`, через ~0–90
  кадров после действия). Старый повтор досылал ещё и свой конец хода → закончил ход врагов раньше времени. Исправлено
  (ждём конец хода от игры).
- Выстрел при повторе вызывает `RequestAction(shoot)` **дважды** (второй — изнутри первого; при игре руками — один раз,
  видимо, игрок перед выстрелом уже в режиме прицела). Итог совпал (враг убит), но патроны могут тратиться дважды —
  проверить. Теперь в логе глубина вложенности `d=` и адреса возврата `bt=` вложенных вызовов.
- ГСЧ у скриптовых подкреплений (Lua, ~30 кадров после конца хода) расходится — ожидаемо, косметика крутит ГСЧ
  каждый кадр; закрывается синхронизацией в конце хода.
- Ход врага бывает пропущен целиком, если у фракции нет живых актёров (в записи нет `turn navy`) — нормально.

**Прогон 2 (2026-11-27, та же миссия, с синхронизацией счётчика):**
- **id подкреплений совпали** (123, 175–177) — синхронизация счётчика работает. Двойного `shoot` не было.
- Все команды игрока до первого хода врага — один в один (позиции, здоровье, граната).
- **Первая же команда ИИ разошлась**: тот же актёр и действие (`enemy_aim`/`shoot`), но другой угол
  (`0x403b64c9` против `0x40390762`); ГСЧ в момент команды разный. Причина: приказы ИИ считает конечный автомат
  `aisimulator.cpp` — `RequestOrders` `0x449a30` ставит `[ai+0x210] = 1`, шаг `0x4487b0` идёт каждый кадр, пока
  состояние не 0 (актёр — `[ai+0x214]`); между шагами косметика крутит ГСЧ, а синхронизация была только в конце хода.
  Исправление: хук шага, строки `ai … s= a= r=`; повтор ставит записанный ГСЧ в начале каждого шага (сопоставление по
  актёру и состоянию, с пропуском до 64 вперёд). Для сети это вариант «ИИ считают все, ГСЧ шлёт хост» —
  если не сойдётся, переходить на «ИИ только у хоста, гостю — готовые команды».
- **Вылет игры** («unexpected exception») ближе к концу: после расхождения повтор опускал счётчик id назад
  (180 → 174 по записанному концу хода) → новые сущности получали id ещё живых → порча реестра сущностей. Теперь
  счётчик только растёт (`# DIFF: entity counter … ahead`).

**Прогон 3 (2026-11-27, та же миссия, ГСЧ на шагах ИИ):**
- **Автодействие игрока**: после последнего выстрела игра сама даёт перезарядку (`o=player … reload fl=1`, через
  ~20 кадров); повтор выдавал её ещё раз (`n=?`). Теперь такая команда от игры засчитывается за запись.
- **Счётчик id всё равно уходит вперёд** (в начале следующего хода 223 против 200): спецэффекты между точками
  синхронизации рождаются в разном количестве. Значит, id не годятся как имена → **актёры по порядковому номеру**
  появления в списке актёров (`actor <id> o=<n>`, поля `ao=`/`to=`), счётчик — без жалоб на расхождение.
- **ИИ разошёлся, хотя ГСЧ на его шаге совпал** (расчёт — один шаг, `s=1`, ГСЧ одинаковый): решение зависит не только
  от ГСЧ — вероятно, от состояния мира/порядка сущностей (id другие). Поэтому **ИИ теперь только у «хоста»**: при
  повторе выполняется записанная команда ИИ этого хода врагов (как гость получал бы её по сети), лишние локальные
  отбрасываются. Это и будет схема сети.

**Прогон 4:** команда игрока ушла в ход врагов (повтор не ждал скриптовых подкреплений) → ожидание теперь учитывает и

**Прогон 5: 29 контрольных точек совпали**, весь первый ход врагов — записанные команды ИИ (`matches`). Расхождение:

## Почему это реально

1. **Игра пошаговая, и действия идут через очередь.** Ход игрока (`PlayerTurnSimulator`) и ИИ (исполнитель приказов
   `0x43be40`) не двигают ботов сами, а ставят запросы в `ActorSimulator`; выполняются они по одному. Значит, по сети
   можно слать **команды** («бот X, действие Y, цель/угол Z»), а не состояние мира.
2. **Один ГСЧ на всю игру**, 8 байт состояния (MWC Марсальи), указатель — глобальная переменная. Перед каждой командой
   обе стороны записывают одинаковое состояние → одинаковые случайности.
3. **Готовая сериализация мира**: сохранение посреди миссии (≈ раз в ход, оно же точка отката) — подключение к
   миссии и починка рассинхрона = передать сейв и загрузить его («Продолжить» → `OnMissionResume`).
4. **Steam P2P без своего сервера**: `steam_api64.dll` игры экспортирует flat API `SteamNetworkingMessages_v002`,
   `SteamNetworkingSockets_v012`, лобби `SteamMatchmaking_v009`, `ISteamFriends_ActivateGameOverlayInviteDialog`.
   Игра сама зовёт `SteamAPI_RunCallbacks` — наши колбэки (`SteamAPI_RegisterCallback`) будут обрабатываться.
   Работает под app id игры (2396240) — Remote Play Together для этого не нужен.

## Главный риск — детерминизм воспроизведения

- Основная симуляция идёт с **переменным шагом**: главный цикл `0xc26c8` → `0x480a10(world, state, &dt)`, dt = время
  кадра × масштаб `game+0x1b70`. Траектории снарядов/рикошеты/падения могут чуть отличаться на разных ПК (разный FPS).
- Перед действием игра делает **предпросмотр исхода** (`OutcomeSimulator`, `0x4548e0` → `0x455060`): та же функция
  мира `0x480a10` крутится с **фиксированным** шагом (`System.UpdatesPerSecond`, по умолчанию 1/60, ≤ 300 тиков) на
  ОТДЕЛЬНОЙ копии состояния (`[sim+0x60]`). Для чего используется результат (камера/ИИ/применяется как итог) —
  **не выяснено**. Если урон/смерти берутся из предпросмотра — детерминизм почти бесплатный.
- Косметика (частицы, idle, реплики) тоже крутит общий ГСЧ, причём по-разному на разных ПК → состояние ГСЧ
  **синхронизировать перед каждой командой**, а не один раз за миссию.

Страховки (в порядке стоимости):
1. **Проверка рассинхрона** после каждого действия: хэш (id, позиция с округлением, HP, модификаторы, живой) всех
   актёров — в Lua есть `GetAllActors`, `GetEntityPosition`, `GetActorHealth`, `HasModifier`.
2. **Мягкая коррекция**: хост шлёт итоговое состояние, клиент правит через Lua (`SetActorHealth`, `SetEntityPosition`,
   `KillObject`, `AddModifier`/`RemoveModifier`) — эти функции уже используются модами.
3. **Жёсткая коррекция**: сейв хоста → клиент перезагружает миссию.
4. Если расхождения частые — патч главного цикла: в тактике кормить мир фиксированными шагами 1/60 (аккумулятор).

## Предлагаемая архитектура (хост-авторитетная пересылка команд)

- **Хост** — у кого кампания (его сейв). Гости получают сейв хоста перед миссией и грузят его в отдельный слот
  (банки сохранений загрузчика уже умеют копировать слоты — `SWH2.Core/Core/SaveBanks.cs`).
- **Владение ботами** — как в моде Coop (`Lua/coop.lua`: ручные списки + раздача). Чужих ботов локально выбирать нельзя
  (DLL уже умеет глушить ввод; здесь — по владельцу, а не по устройству).
- **Ход игрока**: локальная команда своего бота → перехват в DLL до постановки в очередь → отправка хосту → хост
  рассылает всем с порядковым номером и состоянием ГСЧ → все (включая автора) выполняют в одном порядке. Одновременно
  выполняется одно действие на всю команду (как в одиночной игре).
- **Ход врагов**: ИИ работает **только у хоста**; его приказы (`0x43be40` → `0x38b9b0`) пересылаются как команды;
  у гостей ИИ выключен (Lua `DisableAI` или патч). Тогда детерминизм ИИ не нужен.
- **Скриптовые события** (Lua миссий: диалоги, подкрепления, двери) срабатывают от одинаковых событий у всех; если
  расходятся — хост-авторитетно через те же команды (вызов Lua-функции по имени).
- **Транспорт**: сначала простой TCP/UDP по LAN/IP (для отладки), потом Steam (лобби + приглашение через оверлей +
  `SteamNetworkingMessages`).
