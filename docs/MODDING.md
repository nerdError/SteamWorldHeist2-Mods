## Как устроен Lua-мод (проверенный рецепт)

1. Свой модуль `Lua/Mod/<name>.lua` в паке; в `Lua/System/system.lua` после `require_global("System/vector")`
   добавить `require_global("Mod/<name>")`. Модуль выполняется в **глобальном** окружении: есть `io`, `os`,
   `pcall`, `debug`, но **нет** игровых функций (`SpawnWorldText`, `AddModifier`…).
2. В конце модуля `sandbox("MyMod")` — таблица `MyMod` становится видна скриптам миссий.
3. В конец каждого `Lua/Missions/*.lua` дописывается блок-обёртка колбэков (`OnCrewDeployed`,
   `OnFactionTurnBegin(faction)`, …): сохраняет родной колбэк в local, определяет свой, вызывает наш код
   **через `MyMod.safe(...)`** (pcall глобального окружения) и затем **всегда** родной колбэк.
4. Свои строки — новый файл `Language/<lang>_mod.csv` (`ключ<TAB>текст`; у не-en языков в конце строки TAB).
5. Состояние между миссиями/сессиями — только в файле (Lua-state пересоздаётся при каждом входе в миссию).
6. Мод — папка `<игра>\Mods\<Имя>\` (старый стиль: вся папка = структура пака; новый: `mod.json` + `files\`
   или плагин с `ctx.Lua.AddGlobalModule` / `AppendToMissionScripts` / `AddStrings` — правки нескольких модов
   складываются). Установка: `swh2 enable <Имя>` + `swh2 install` (игра должна быть закрыта).

## Чит-меню (CheatMenu)

Код: `Mods/CheatMenu/` — `Lua/cheats.lua`, `Lua/mission_hook.lua`, `Lua/modifiers.xml.txt` (встроены в dll),
`CheatMenuMod.cs` (установка + `IModTool` + `IModCommand`), `CheatForm.cs`, `CheatClient.cs` (протокол ниже).

Родное меню вырезано из exe (EXE_NOTES → «Отладочное меню»), а Lua не читает клавиатуру и не рисует UI, поэтому
меню живёт в нашем приложении и общается с модом через файлы в `%APPDATA%\Thunderful\SteamWorld Heist II\`:
- `swh2_cheats_cmd.txt` — команды от приложения (`<id> <unixtime> <cmd> [arg]`, дописываются в конец). Мод
  раз в 15 кадров переименовывает файл в `.work`, читает и удаляет. Разовые команды старше 10 с отбрасываются
  (`expired`), чтобы клик вне миссии не сработал в следующей.
- `swh2_cheats_state.txt` — переключатели (`god/freeze/spinup`), переживают миссии и перезапуск игры.
- `swh2_cheats_status.txt` — heartbeat раз в ~2 с: текущий скрипт миссии, время, переключатели.
- `swh2_cheats.log` — результаты (`ok/error/unknown/expired`) и ошибки Lua.

Команды: `win` (`EndMissionInVictory`), `heal`, `kill` (`KillObject` всем врагам; может сломать скриптовых
боссов), `weaken` (врагам 1 HP), `alarm_off`, `give <item>` (`GiveItem(item, true)`). Переключатели — свои
модификаторы в `modifiers.xml` на встроенных `StatusFlags`: `cheat_god` = `invulnerable, buddha`,
`cheat_spinup` = `spin_up` (атака не завершает ход), `cheat_freeze` = `ai_disabled`. Модификаторы
досинхронизируются раз в секунду, при высадке и в начале каждого хода (ловят подкрепления).
Ограничения: работает только в миссиях (у карты мира нет `OnUpdate`), денег/опыта напрямую не даёт.

### Грабли, на которые уже наступили
- В песочнице миссий **нет `pcall`/`error`/`setmetatable`/`io`/`os`/`_G`** (белый список — EXE_NOTES).
  Вызов `pcall` в обёртке падал → родной `OnCrewDeployed` не вызывался → ломались стартовые события миссий.
- Генератор мода должен читать **оригинальный** пак (бэкап), а не установленный — иначе хуки удваиваются.
- `io.popen`/`os.execute` мигают окном консоли.
- Сырой текст в `SpawnWorldText` не показывается (`!missing line`) — нужен ключ локализации.
- Ключ, дописанный в самый конец `en.csv`, не подхватился — использовать `<lang>_mod.csv`.
- 60 из 151 миссий (процедурные) **без Lua-скрипта** — хуки там не работают; чтобы покрыть их, нужно
  добавить `<Script>` в определение миссии (`missions*.de`) — ещё не проверено.
- Перезапись exe целиком (`open(..., "wb")`) в этом окружении падает с `Invalid argument` — писать на месте.
- Python-правки файлов через heredoc ломают экранирование (`\t`, `\r\n`, `\\`) — править через Edit или
  отдельный файл; после генерации Lua — синтаксическая проверка + `sim_sandbox.py`.

## Мод скорости боя (`turbo`)

Механизм (подробно — EXE_NOTES, «Скорость боя»): тактический мир каждый кадр считает масштаб времени и
пишет его в `game+0x1b70`; на него умножается dt всей симуляции. Патч перехватывает эту запись и выбирает
множитель по текущей последовательности (катсцена/диалог → ×1, показ врага/турели/подкреплений → `×intro`)
и по текущей фракции (не `"cowbots"` → `×enemy`). Код — в собственной секции `.swh2` (4 КБ, места много).

```
python tools/re/exe_patch.py apply turbo --enemy 3 --intro 6
python tools/re/exe_patch.py apply turbo no_checkpoints --enemy 3 --intro 6   # несколько патчей — одной командой
```
Каждый `apply` собирает exe с оригинала, поэтому перечислять нужно ВСЕ желаемые патчи сразу.
Для игроков это мод **Turbo** (`Mods/Turbo/Turbo.cs`: те же байты + таблица rel32-релокаций, секция может
встать по любому адресу); `exe_patch.py` — только для прототипов.

Известное ограничение: общий масштаб времени ускоряет и «косметику» (анимации шляп, idle) во время ходов
врагов — в движке одно время на всё. Разделить можно только точечными патчами конкретных систем.

Возможные доработки:
- Уменьшить `IntroCameraLingerTime*` в `game_constants.xml` (data-мод), если показы всё ещё долгие.
- Горячая клавиша вкл/выкл или настройка без перепатчивания (нужно место под код → DLL).
- ~~Перенести патчер в C#~~ — сделано: мод `Mods/Turbo` (настройки enemySpeed/introSpeed в GUI).
- Если понадобится больше кода в exe: DLL-загрузчик (прокси `dxgi.dll` в папке игры + MinHook) —
  тогда же можно регистрировать свои Lua-функции (регистраторы — EXE_NOTES, «Регистрация Lua API»),
  например `SetTimeScale`, вызываемую из Lua-хуков.

## Челлендж «без гринда» — как устроен

Источники бесконечных наград и что с ними делается (только XML, без Lua):
- Флагманы/артефакты (`ReputationSpawns`) респавнятся каждый день, после взятия предмета дают «призрачный» лут
  (`worldmap_ghost`) → `RespawnIfAchievedReputation="false"` + обнулённый `worldmap_ghost`.
- Плавающий лут `wm_loot` (спауны `*_loot` в `worldmap_spawns.xml`) → `Count 0`.
- Корабли на карте (`WM_ENEMY_SHIP`, `WM_ENEMY_SHIP_BIG`) → пустой `LootEntity` (как у мины). Мастер-лут флагманов
  спаунится кодом отдельно (`wm_enemy_ship_master_loot`) — должен остаться, проверить в игре.
- Повторы миссий: репутация за повтор не растёт, мастер-лут разовый, но ящики и опыт — каждый раз. Решение: на каждую
  боевую миссию с карты квест `nogrind_won_X` (`mission_static` X, активен с начала) → `nogrind_lock_X`
  (`UnlockedBy` = won + все квесты с условием `mission` X, цель `none`, `LockMissions` X). Квесты с условием `mission`
  засчитываются только если активны в момент победы, значит игра ждёт повтора (Фабио `east_caribbea_boss_01`:
  `fabio_glow_rod`, `east_caribbea_navy_npc_bar`) — поэтому замок ставится после них. Если такой квест так и не
  открылся (другая ветка), миссия остаётся открытой — список в spoiler.
- `quests.xml` при этом переписывается целиком (XmlWriter): меняются только пробелы в тегах.

Что проверить в игре: замок появляется после победы; Фабио открыт до реванша; флагман после добычи не возвращается;
корабли без лута, флагманский предмет выпадает. Известные дыры: опыт/лут при отступлении или поражении (можно ли
фармить ящики выходом из миссии) — не исследовано; бары/магазины/roaming-миссии не трогаются.

## Челлендж «без чекпоинтов»

Отключает «Load Checkpoint» в миссиях (меню паузы и попап при провале цели). Теперь — настройка `noCheckpoints`
мода **Challenges** (`Mods/Challenges/NoCheckpoints.cs`). Через XML нельзя:
`SaveRestorePoints=0` уронит игру, `1` всё ещё даёт откат к началу хода (подробности — EXE_NOTES,
«Точки отката»). Это exe-патч (в моде Challenges).
Проверить в игре: кнопка серая; при провале обязательной цели — только «вернуться на карту»;
выход в меню посреди миссии и «Продолжить» откатывает к последнему сохранению миссии. Каждое сохранение
(`0xccc00`) заодно кладёт точку отката (`0xccf64` → `0xc6c50`), а игра называет точки «N ходов назад» —
значит сохранение ≈ раз в ход, и выход = откат к началу хода. Закрывает отдельный переключатель
`quitForfeits` (`QuitForfeits.cs`): в скрипты боевых миссий с `Abortable≠false` (65 шт.; не tutorial/prisonbreak,
не корабль/бары/магазины) дописан хук `OnMissionResume` → через 10 кадров `ExitMissionToWorldMap()` из `OnUpdate`.
`OnMissionResume` — родной колбэк загрузки миссии из сейва (игра использует его в `prisonbreak.lua`).
Проверить в игре: (1) меню выхода пишет «last save N seconds ago» — сколько это после нескольких действий
(если игра сохраняется после каждого действия, опция не нужна); (2) выход → Continue → карта, без падения;
(3) обычный старт миссии не выкидывает. Lua `SaveCheckpoint()` для ironman не годится: это «скриптовые
чекпоинты» tutorial/prisonbreak, которые игра сама грузит при провале цели (`0x3ac69d`).

## Новый контент (миссии, регионы) — что известно

Цель пользователя: свои миссии/области и, в перспективе, визуальные инструменты, которыми можно поделиться.
- **Уровень миссии — не отдельный файл, а раскладка комнат** в `missions*.de`: `<Rooms><Room Type=<комната из
  Patchsets/*.le> Position="x, y" Id=GUID/>`, связи дверей `<OpenPortals><Portal RoomA RoomB PortalA PortalB/>`
  (PortalA/B — битовые маски), `<Entrances>`, `<SpawnMarkers>` (имена для `FixedSpawns`/`MasterLoot`).
  Комнаты (`.le`) рисовать не нужно — редактор миссии = «расставь готовые комнаты на сетке». У миссий без
  `<Rooms>` раскладка генерируется.
- **Карта мира читается из `WorldMap/Maps/WorldMap.tmx` при запуске** (`game_constants.xml` → `<WorldMap>`,
  в exe свой парсер Tiled) — значит, её можно править в Tiled. Миссия на карте = объект `gid="5"` со свойством
  `Mission` в слое `Entities`; регион = полигон в `Regions` со свойством `WorldMapRegion`. Группы `0..9` — слои
  глубины (лежат рядом, не вложены; поверхность — `0`/`1` `Main`). Координаты объектов: тайл = `x // 216`,
  `y // 216` (изометрия 432×216). В `Main` ненулевой тайл — скала, 0 — вода. `nextobjectid` в `<map>` нужно увеличивать. `Game2.pak/WorldMap/WorldMap.xml` — только
  проектный файл Tiled (типы свойств), не карта.
- Строки: загрузчик читает все `Language/<lang>_*.csv` → у каждого мода свой суффикс (`_newmission`), без
  конфликта с CheatMenu (`_mod`).
- Моды включаются `swh2 enable A B` (или `install --only A,B` разово, через запятую).

**NewMissionTest** (шаг 1): миссия `mod_test_01` — копия раскладки `west_caribbea_02` (новые GUID), свои правила,
скрипт (реплика «This ship wasn't here yesterday...» при высадке), трофей `crossbow_03_rare`.
Установка: `swh2 enable CheatMenu NewMissionTest` + `swh2 install`.
**2026-11-22, проверено в игре (иконка у `west_caribbea_02`):** миссия появляется, запускается, наш скрипт и строки
работают. Затем иконка перенесена к бару Angler's Reef (`ANCHOR`/`REGION`/`SHIFT` в генераторе; проверка полигона

начинает в Angler's Reef. Ещё не проверено: победа/трофей засчитываются, сейв, репутация/процент региона.

### Своя кампания — разведка (2026-11-22) и TestCampaign

- **В exe нет ни одного имени квеста или миссии** (кроме `base`/`home`) — сюжет целиком в данных и Lua. Квесты по
  имени упоминают: `worldmap.lua` (скрипты карты, ~35 квестов), `Lua/Intermissions/*`, бар `west_caribbea_a_bar.lua`,
  `home.lua` (финал: `PlayMovie("Movies/outro")` + `EndCredits()`), `conversations.xml` (`Case If="quest_active:…"`,
  `QuestObjective`), `personas.xml`, `intermission_cutscenes.xml`, `missions*.de`, `outsets.xml`, `game_constants.xml`
  (`TutorialPopup*QuestRequirement`). Поэтому квесты **не удаляем, а «паркуем»**: `UnlockedBy` = вечный скрытый
  квест (`Condition none`) — все ссылки остаются валидными, сюжет не стартует.
- **Грабли (2026-11-22, v1 и v2 сломались в игре одинаково):** все 222 квеста стартовали разом (лавина квестов,
  катсцены всей игры при выходе из бара, бар и миссии заперты чужими `LockMissions`/`LockAllMissionsExcept`).
  Причина (видно в сейве): **завершение квеста завершает и его предпосылки `UnlockedBy`** — квесты из
  `CompletedQuests` стартового набора завершили общий вечный квест, а от него зависело всё. (В обычном старте без
  туториала так же завершаются `tutorial_build_ship_equipment_station` и др., которых нет в списке.) Решение v3:
  **у каждого квеста свой вечный квест** `mod_park_<имя>`. Ложный след v2: парсер (`0x233190`) на ссылку вниз по
  файлу только пишет WARNING («Quest {} is unlocked by non-existent quest {} (or the latter is further down in the
  file)»), имя сохраняет; а вот зависимость без определения проверки пропускают (`0x11ca50` — проверка skippable,
  `+0x110` = IsSkippable) → квест-фантом в `UnlockedBy` = квест открыт. Генератор держит определения выше
  использования (`check_unlock_order`). Закомментированные квесты в файле есть — не трогать.
- **Сейв** (`%APPDATA%\Thunderful\SteamWorld Heist II\<steamid>\Save000\savegame_00N.dat`, `SWH2`+чанки, не сжат):
  квесты — записи `Qest` + заголовок + имя; заголовок 9 байт = завершён, 17 байт = активен (по сравнению сейвов).
  Лучший способ отладки квестов — смотреть сейв после теста.
- Полная документация квестов — комментарий в начале `quests.xml` (условия `mission`/`mission_static`/`quest`/
  `conversation`/…, `UnlockedBy` — список через запятую, `LockMissions`, `LockAllMissionsExcept`, кордоны, слои
  карты, `ItemRewards`, `OnUnlocked/OnCompleted` с `MapConversation`/`MapScript`/`TacticsScript`/`TacticsConversation`).
  **Порядок квестов и целей должен совпадать с сейвом** → своя кампания = новая игра.
- Старт: `outsets.xml` (`new_game` / `new_game_skip_tutorial` — бар Angler's Reef, `CompletedQuests`, туман,
  команда daisy+wesley); какой берётся — `game_constants.xml` `NewGameOutset*`.
- Иконка миссии на карте умеет `Hide If Locked By Quest` (bool) — скрыта, пока миссия заперта `LockMissions`.
- Диалог = `<Conversation Name><Speak Speaker="captain" Text="<ключ строки>" Id="<6 симв.>"/>` в `conversations.xml`.
- Миссии через `ReputationSpawns`: только `arctica_boss_01`; `worldmap_spawns.xml` миссий не спаунит.

## Хардкор и мутаторы (Challenges 1.1)

- Колбэка поражения у движка нет (таблица имён колбэков в exe — `0xb785d8…0xb787c8`: есть `OnMissionVictory`,
  `OnMissionResume`, нет ни `OnMissionEnd`, ни defeat). Поэтому One life: свежий старт боевой миссии (не resume)
  пишет прогону `in_mission`, `OnMissionVictory` — `won`; если при следующем старте всё ещё `in_mission` — проигрыш.
  Состояние — в `%APPDATA%\Thunderful\SteamWorld Heist II\swh2_hardcore_runs.txt` по id прогона; id записан в
  сейв как выполненные скрытые квесты `swh2_run_bit_0..19` (квест нельзя «откатить», поэтому сами квесты
  состояние хранить не могут). Конец игры: квест `swh2_hardcore_lost` → `swh2_hardcore_game_over`
  (видимая цель + `LockMissions` всех боевых миссий). Не отслеживаются скрипты, уходящие из миссии без победы
  (`EndMissionInstant`/`ExitMissionTo*`/`ChangeMission`: финал с Кракеном, `old_heist`).
- Permadeath: `OnEntityKilled` члена экипажа → квест `swh2_scrapped_<persona>`; при высадке такой бот получает
  `KillObject`. Персона = `GetEntityName` (бойцы названы по персоне), запасной вариант — `TacticsEntity`.
- Процедурные боевые миссии без скрипта (15 шт.) получают `<Script>Lua\Missions\swh2_generic.lua</Script>` —
  только когда включён любой Lua-челлендж и только те, которым раньше не дал свой скрипт рандомизатор.
  Хуки во все добавленные модами скрипты идут через `LuaPatcher.AppendToMissionScripts` (с загрузчика 1.1 он
  видит и файлы, добавленные модами, — `GameContent.FindAdded`).
- Мутаторы — чистый XML: `ExplosiveDamage` с `DamageRadius` на каждом оружии (как у `sniper_01_rare`),
  `EffectOnEnd` у снарядов; модификатор `swh2_death_blast` (`On="Death" Handler="Explode"`) во `InnateModifiers`.

Проверить в игре: (1) квесты, выполненные в миссии, сохраняются и после поражения (иначе первый id может
потеряться); (2) `OnMissionVictory` вызывается при любой победе, в т.ч. эвакуации; (3) `<Script>` у процедурной
миссии грузится; (4) `KillObject` бота при высадке не ломает миссию; (5) `LockMissions` закрывает миссии и
квест «Game over» виден; (6) взрыв у пуль виден и бьёт по радиусу; (7) `Explode` на `Death` срабатывает;
(8) HP: экипаж 1, рядовые враги 1, боссы со своими фазами.

## Челленджи — идеи и что для них есть

- Лимит ходов: хук `OnFactionTurnBegin` + счётчик → `EndMissionInDefeat`.
- Дебафф/мутатор на миссию: `AddModifier(actor, "<modifier>")` по `GetFriendlyActors()` (модификаторы —
  `Definitions/modifiers.xml`), выбор по сиду; эдикты (`edicts.xml`).
- Ограничения экономики/лута — чистые XML-правки (как в рандомизаторе).
- Сложность выше veryhard — новый пресет в `difficulty_presets.xml`.
- Неиспользуемые игрой Lua-функции (41 шт., LUA_API.md, «Вызовов» = 0) — проверять в игре перед использованием.

## Рандомизатор 1.4: хаос в миссиях (Lua) и прочее

  геймпад N). Игра каждый кадр опрашивает ВСЕ геймпады в одном цикле и складывает их (`0x7f4d18`, список контроллеров,
  хэндл SDL в `+0x48`, последний активный — `0xe669f4`), клавиатура/мышь — `SDL_PollEvent` (`0x7f9520`),
  `SDL_GetKeyboardState`, `SDL_GetMouseState`. Привязки — `Controls/default_controls.cfg`.
  - Патч exe: единственный `call [SDL_Init]` (`0x7f8a7a`) → заглушка в секции `.coop`: `LoadLibraryA("Mods\Coop\swh2coop.dll")`
    (IAT `0xb47180`, путь относительный — рабочая папка = папка игры), затем `jmp [SDL_Init]` (IAT `0xb47870`).
  - DLL (`Mods/Coop/native/swh2coop.c`, cl /MT, сборка — target в Coop.csproj через `native/build.cmd`) в DllMain меняет
    слоты IAT `GetButton 0xb478b8`, `GetAxis 0xb47830`, `PollEvent 0xb47860`, `GetKeyboardState 0xb47930`,
    `GetMouseState 0xb47800` (проверяя, что там именно эти функции SDL2). Номер геймпада = ранг instance id среди
    опрошенных за 1,5 с (порядок подключения). Всем доступны: Start, правый стик (камера и клик), LB/RB; Q/E/Tab/M/1–6/стрелки;
    остальное — только у разрешённого устройства (мышь при блокировке «замораживается»).

    выбранного бота; файл старше 2 с = `all` (карта, меню, пауза?). DLL пишет `swh2_coop_blocked.txt` при заглушённом
    нажатии → Lua показывает имя владельца над выбранным ботом. Лог DLL — `swh2_coop_input.log`.
  - Офлайн-тест фильтров: `Mods/Coop/native/test.cmd` (поддельные функции SDL).
  - Remote Play Together для игры недоступен (пользователь проверил) — основной путь Parsec (у каждого гостя свой геймпад).

## Кузница (вырезанная механика) — что осталось

- Данные: `forge_recipes.xml` (6 рецептов: деталь `weaponpart_<класс>` → один из `<класс>_01..03`),
  `weapon_parts.xml` (только абстрактный `WEAPONPART_BASE`, `itemclass_weaponparts`, `LootCost` 20 — самих деталей нет),
  поле `ForgeTier` в описании `ship_upgrades.xml` (ни у одного апгрейда). Строки `ui_forge_*` помечены
  `UNUSED, DON'T TRANSLATE`; `ui_interact_forge` есть, но нигде не используется; в `UI/ui.me` — только анимация `forge`.
- Exe: парсеры `ForgeRecipeDefinition` / `WeaponPartDefinition` живы (файлы грузятся), `ForgeTier` читается.
  `ForgeSimulator` — объект 0x18 байт с одним виртуальным деструктором, создаётся в `0x47e720` рядом с другими
  «симуляторами» (`AlarmSimulator`) и кладётся в слот `+0x498`; логики кузницы и экрана нет — вырезаны.
- Вернуть можно только своей реализацией: детали как предметы (`special_items`/`utilities` с `LootTables`), а
  «ковка» — через квест с условием `item` (наличие детали) и `ItemRewards`, или Lua (`RemoveItem` + `GiveItem`) из
  переключателя на карте/в лодке. Проверки количества предметов в Lua нет (`HasItem` отсутствует).
